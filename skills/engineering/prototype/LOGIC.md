# 邏輯原型

一個小型互動終端應用程式，讓使用者手動驅動狀態模型。當問題是關於業務邏輯、狀態轉換或資料形狀時使用。

## 何時適用

- 「我不確定這個狀態機是否處理 X 然後 Y 的邊界案例。」
- 「這個資料模型真的能讓我表示…的情況嗎？」
- 「我想在寫之前感受一下 API 應該長什麼樣子。」

若問題是「這應該長什麼樣子」——錯誤分支。使用 UI.md。

## 流程

1. 陳述問題。在寫程式碼之前，寫下你正在原型化的狀態模型和問題。
2. 選擇語言。使用主專案使用的語言。
3. 將邏輯隔離在可攜式模組中。將實際邏輯放在一個小的、純粹的介面背後，之後可提取到真實程式碼庫中。保持純粹：無 I/O、無終端程式碼。
4. 建立最小的 TUI 來暴露狀態。每次 tick 清屏並重新渲染整個畫面。每幀兩部分：當前狀態 + 鍵盤快捷鍵。
5. 使其一個指令可執行。加入專案現有任務執行器。
6. 交給使用者。他們會自己驅動。
7. 擷取答案和原型。將驗證過的邏輯模組提升到真實程式碼中。

## 反模式

- 不要加測試、不要接真實資料庫、不要一般化、不要把邏輯和 TUI 混在一起、不要將 TUI 外殼送到生產環境。
