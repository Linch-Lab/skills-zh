# 撰寫優秀 Skills 的參考指南

Skill 存在的目的是從隨機系統中榨取出確定性。可預測性——agent 每次跑都走相同的**流程**，而非產出相同結果——是根本美德；以下每個槓桿都為此服務。

## 調用方式

若需禁止自動調用，在 description 最前方加上「此 skill 禁止自動調用」。

- 禁止自動調用：description 開頭標註，agent 看到後應跳過
- 允許自動調用：不標註，agent 自行判斷何時載入

本 skill 禁止自動調用。

## 寫描述

Model-invoked 的描述做兩件事：說明 skill 是什麼，並列出應觸發它的情境分支。每個字都增加 context 負荷，所以描述比內文更值得精簡：

- 把 skill 的**引導詞**放在最前面——描述是它發揮調用作用的地方。
- 每個分支一個觸發詞。同義詞只是重複——把它們合併；只保留真正不同的分支。
- 砍掉內文已經有的身分說明。描述只留觸發詞，加上「其他 skill 需要時可引用」的條款。

## 資訊階層

Skill 由兩種內容構成——步驟和參考——可以自由混合。核心決策是每段資訊放在階層的哪一層：

1. **內文步驟**——SKILL.md 中有順序的行動，主要層級。每一步以一個**完成條件**結束，告訴 agent 工作完成了。條件必須**可檢查**（agent 能分辨做完/沒做完？），且必要時**窮盡**（「每個修改的 model 都考慮到」，不是「產出一份變更清單」）。
2. **內文參考**——SKILL.md 中的定義、規則、事實，按需查閱。
3. **外部參考**——推到 SKILL.md 以外的獨立檔案，透過上下文指針觸發時才載入。

階層決定放多深，**共置**決定放一起：一個概念的定義、規則、注意事項放在同一標題下，讀其一即帶出鄰居。

## 何時拆分

每次拆分消耗兩種負荷之一，所以只在值得時才切：

- **按調用拆分**：當有一個獨立的引導詞應單獨觸發，或其他 skill 必須引用它時，拆出 model-invoked skill。
- **按序列拆分**：當後面的步驟誘使 agent 急著完成前面的步驟時（過早完成），把後續步驟隱藏起來。

## 修剪

- 每個意思只保留一個**權威來源**。
- 逐句檢查：刪除那句後行為會改變嗎？不會→刪掉。
- 積極刪——大多數未通過測試的段落應該刪掉，不是重寫。

## 引導詞

引導詞是模型預訓練中已有的緊湊概念（如「tight loop」「tracer bullet」「red/green」），用最少 token 錨定一大塊行為。

- 在**內文**中錨定執行：agent 每次看到這個詞就走向相同的行為。
- 在**描述**中錨定調用：當同樣的詞出現在你的 prompt、文件、程式碼中時，agent 更可靠地觸發這個 skill。

多個地方反覆描述同一個概念→用一個引導詞取代。少 token，更準確。

## 常見失敗模式

| 模式 | 症狀 | 解法 |
|---|---|---|
| **過早完成** | agent 步驟沒做完就跳下一步 | 先強化完成條件；仍發生則拆分序列 |
| **重複** | 同一意思出現在多處 | 合併為單一權威來源 |
| **沉積** | 不敢刪的舊內容層層堆疊 | 定期修剪 |
| **蔓延** | skill 太長，即使每行都有用 | 用階層把參考推到外部，按分支拆分 |
| **無效行** | 模型本來就會做的事還寫出來 | 刪掉，或用更強的引導詞取代 |
| **否定** | 「不要想大象」反而讓大象更顯眼 | 改成正向陳述；禁止條款只在無法正向時保留，且必須配對「改做什麼」 |
