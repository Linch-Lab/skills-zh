# 用途

此文件規範如何撰寫新的 Skill。

---

## 術語定義（全文通用）

| 術語 | 定義 |
|------|------|
| 精簡詞 | 單一詞彙代表一組行為。範例：「紅燈」= 遇錯即停 |
| 完成條件 | 步驟結束時可明確檢查的標準。代理能判斷「做完」或「未做完」 |

---

## 規則

### 規則一：調用模式由 description 決定

| 模式 | description 寫法 | 行為 |
|------|-----------------|------|
| 手動調用 | 開頭寫「此 skill 禁止自動調用」 | 代理看到標記後跳過，不主動載入 |
| 自動調用 | 不寫禁止句，關鍵字觸發 | 代理自行判斷載入時機 |

> 本 Skill 採用第一種（手動調用）。因無觸發關鍵字，使用者須手動輸入名稱呼叫。

---

### 規則二：Description 三條限制

撰寫 description 時：

1. 開頭放精簡詞
   - 錯誤：「此技能用於協助使用者撰寫測試驅動開發的代碼」
   - 正確：「TDD — 測試驅動開發。觸發：測試優先、紅綠重構」

2. 每種觸發條件只寫一次
   - 錯誤：「測試驅動開發、TDD、測試優先開發」（三者同義）
   - 正確：「TDD、測試優先、紅綠重構」（三者不同面向）

3. 不重複主文內容
   - 錯誤：description 寫了步驟細節
   - 正確：description 只寫觸發條件和銜接句

---

### 規則三：每步驟須有完成條件

完成條件必須可檢查。

| 錯誤 | 正確 |
|------|------|
| 產出變更清單 | 每個修改過的模型均已記錄在清單中 |
| 完成測試 | 所有測試案例通過，無跳過 |

---

### 規則四：用正面敘述取代負面禁止

| 錯誤 | 正確 |
|------|------|
| 不要跳過步驟 2 | 依序完成步驟 1 到 3 |
| 別忽略錯誤 | 遇到錯誤即停止並回報 |

---

## 常見錯誤速查

| 錯誤 | 修正 |
|------|------|
| 步驟未完成就自認做完 | 強化完成條件，或拆分步驟 |
| 同概念寫在多處 | 集中到術語表 |
| 舊內容堆積 | 執行修剪 |
| 主文太長 | 參考資料移出到外部文件 |
| 寫了不改變行為 | 刪除或換成精簡詞 |
| 用「不要 X」引導 | 改寫為「要做 Y」 |

---

## 拆分時機

| 情況 | 判斷標準 | 做法 |
|------|---------|------|
| 一個技能裡有兩套不同功能 | 同一個 description 裡有多組不相關的觸發關鍵字 | 把次要功能拆成獨立技能 |
| 前置步驟被後續步驟干擾 | 代理知道後面還有事要做，會急著跳過前面 | 把後續步驟移到外部文件，或拆成兩個技能 |

---

## 輸出前檢查清單

- [ ] description 開頭是否標註「此 skill 禁止自動調用」？（手動調用技能適用）
- [ ] 每個步驟的完成條件是否可檢查？
- [ ] description 是否只寫觸發條件，沒有偷渡主文步驟？
